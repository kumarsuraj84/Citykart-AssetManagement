## 5. Decisions taken where the brief was open

1. **One People screen for four kinds** (a `kind` prop) rather than four copies; the old combined `AssetUsersScreen` is retired (its route only redirected) — every test intent ported.
2. **Head-office admin rows are listed** (the server's paging counts them) with "Head-office Admin" and "Head-office admin only"; before, they were filtered out on the client.
3. **Edit** sends only changed fields (the S1 partial PUT), so a work area nobody touched is never sent (replaces "send the stored value back"). Company is shown, not edited, on Edit (moving a person between companies is not a daily edit; Company access covers extra companies). A store's code is read-only on Edit (its rooms are named after it).
4. **Employee login**: Work Area starts as the editor's own when they have one area, else Both; extra companies are offered only for someone in more than one company; the email is required only when the person can sign in; no password is ever set by the form.
5. **Store place** is optional ("The store's own place (made for you)") — the server's rule; another existing or new place can be chosen.
6. **Issue passwords, ticked accounts** use `only_without_password: false` (the admin chose them; a replaced password is said in the confirmation). "Every … without a password" counts from the list first so the confirmation can say N; the server re-decides (owners and the caller are never included).
7. **Passwords are not handled by React Query** at all (direct `apiClient.post` into dialog state), so nothing lingers in the mutation cache; the single Reset password was moved to the same pattern.
8. **Reports**: three tabs; the preview starts unfiltered (the whole scoped register) so the page is never empty; the export and the preview share one query-string builder; Person / Place uses the same `/asset-users` picker as the register (see §8).
9. **Home** keeps `/reports/dashboard` for the tables and status counts and uses it as the fallback for "Needs attention"; the ERP-needing-input row (new) links to Purchase Orders › From ERP.
10. **Set-up status refresh**: a mutation-cache subscription re-asks `/setup/status` after any successful save while the wizard / Home row / landing is mounted (plus an explicit invalidation after Add Store, which does not use a mutation).
11. **Item sets**: a set chosen from the list that is not the Item's own is pointed at, not edited (the server refuses changing another Item's set); the Item's own set is sent as `set_parts` only when its parts changed.
12. **Group deactivation**: disabled only when the list *shows* active children; with unknown counts the server's refusal sentence is shown as written. Bulk deactivation is not pre-blocked (the server lists each refusal).
13. **ERP draft**: the cap is computed live (`open_units − others`), so units can move between two lines of one code; `max_units` (computed for the drafted quantities) is the fallback.
14. **Serial Pending** reads all pages up to 5,000 (client-side filters stay correct); above that it says how many are listed.

4. `PUT /api/asset-users/{id}` answer in the `PersonOut` shape (today `AssetUserOut`), so the list row can be patched without a refetch.
5. Optional: `GET /api/assets?serial_pending=true` with `limit` up to 1,000 (like `ids`), so Serial Pending needs fewer pages.
6. Optional: `GET /api/home/attention` → `erp_pos_needing_input` broken down by company, for a direct link with the company chosen.
7. Repeat (S5b-1 F8): register `subcategory_id` filter; batch-add `problems[].field`.
