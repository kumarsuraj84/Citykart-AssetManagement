How to read it
- OBS-TV: the pre-WP-A2 `end_all_sessions` (read, add 1 in Python, write) loses 18-19 of 20 simultaneous session
  ends; the shipped single `UPDATE ... SET token_version = token_version + 1 RETURNING` loses none.
- Race probes: every renewal's commit was artificially held 0.5 s, so the winner keeps its row lock. At +0.25 s
  pg_stat_activity shows the 9 other renewals WAITING on that lock -- the "exactly one rotation" result is real
  database serialisation, not luck of scheduling. With the default 10-second grace all 9 losers are harmless
  DUPLICATEs (access token only); in strict mode (grace 0) the first loser is REUSE (all sessions ended, one
  revoked row) and the rest find the sessions already ENDED -- never a second rotation. (The long "slowest
  renewal" times come from the artificial 0.5 s per commit; the losers queue on the row one after the other.)
- Lock order: PostgreSQL keeps a lock on the newest row version a waiting UPDATE re-checked, until that
  transaction ends. The first draft then took the person's row (token_version) while still holding the session
  row; a sign-out holds the person's row and wants the session rows -> "deadlock detected" (one request would
  have been a 500). The shipped `_finish` commits (releases) first and bumps with `only_if_version`, so the same
  interleaving ends cleanly ('ended'). Permanent regression test:
  tests/auth/test_wpa2_refresh_reuse.py::test_renewals_reuse_and_sign_out_at_the_same_moment_never_fail_with_an_error
